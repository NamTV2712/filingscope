# Open-source and paper research

Research status checked 2026-11-11. Findings below are design inputs and
experiment candidates; no external framework is treated as proof that FilingScope
will improve. Re-check license, versions, model terms, and resource needs before
adding a dependency or copying code.

| Source | Problem and method | License / maintenance / resource profile | Applicability and next experiment | Decision |
|---|---|---|---|---|
| [FinSAgent paper](https://arxiv.org/abs/2607.18102) | SEC QA framework combining role-specialized agents, database-aware query decomposition conditioned on a summary-level local-corpus view, and multi-path retrieval with feature-gated reranking. The authors report results across five offline benchmarks and a user-rating study. | Research preprint, not a dependency. The arXiv source did not link a public code repository; implementation/data licensing and independent reproducibility remain unverified. | M4 tested the corpus-conditioned planning hypothesis separately: BM25 Recall@10 rose 4.34 points overall and 2.22 held-out points, while p95 BM25 latency rose to 1,051 ms. This does not reproduce the paper's multi-agent/reranker system or establish answer-quality gains. | **ADAPT** the Corpus Map hypothesis only; no code or framework adoption. See [`M4 results`](CORPUS_AWARE_PLANNING.md). |
| [FinRank paper](https://arxiv.org/abs/2608.07400) and [dataset repository](https://github.com/datanxt/FinRank) | 1,185 manually authored records across 22 companies, with gold passages and curated same-company/year/metric and cross-company negatives; retrieval, reranking, and hard-negative discrimination are separate. | Dataset/code license must be checked at acquisition. New benchmark, not a runtime dependency. Annotation/distribution limitations are disclosed by the authors. | Inspect split and license; map negative types into M12, then evaluate a legally usable fixed subset. | **EXPERIMENT** as an independent retrieval design. |
| [Fin-RATE paper](https://arxiv.org/abs/2602.07294) | Separates within-disclosure detail, cross-entity comparison, and longitudinal tracking; reports degradation as task scope broadens. | Research paper/dataset terms must be checked before use; no dependency. | Use task taxonomy to stratify M12/M13 and avoid overfitting to single-document questions. | **ADAPT** taxonomy only; verify access/licensing before scoring. |
| [When the Reranker Becomes the Decision Layer](https://levelup.gitconnected.com/when-the-reranker-becomes-the-decision-layer-de7309e5efd7) | Describes Jev's Noul/Choice/Score decision primitives for pre-retrieval gating, candidate scoring, citation checks, and cost-aware routing, with deterministic ordering around model outputs. | Secondary practitioner article, not independent validation. Its demonstration compares five pipelines on eight in-scope and two out-of-scope questions over a small corpus; results do not transfer to financial filings. No dependency/license relevance. | M3 adapted the decision-boundary pattern into typed observations plus deterministic policy, and compared it to a score-only baseline on 60 synthetic cases. A real Jev/TypeSafe backend remains a separately gated experiment requiring external financial labels, privacy/cost review, and probability calibration checks. | **ADAPT** the architecture hypothesis; **DEFER** Jev. |
| [LangGraph](https://github.com/langchain-ai/langgraph), [StateGraph](https://reference.langchain.com/python/langgraph/graph/StateGraph), and [Send](https://reference.langchain.com/python/langgraph/types/Send) | Typed graph state and dynamic dispatch of independent tasks. | MIT. FilingScope pins `langgraph==1.2.20`. | M5 and M7 provide bounded routes. M8 uses Send, a deterministic receipt reducer and [RunnableConfig concurrency](https://reference.langchain.com/python/langchain-core/runnables/config/RunnableConfig) for scoped filing retrieval. | **ADOPT** finite routing and bounded filing fan-out. [M8 latency and limits](PARALLEL_RESEARCH.md) |
| [deep_agent_financial_research](https://github.com/langchain-samples/deep_agent_financial_research) | Example of subagent context isolation, delegation, and step/time budgets for financial research. | Repository license and current maintenance must be verified before code reuse. README stack includes external Snowflake MCP, LangSmith, and model gateway dependencies; resource cost depends on hosted services. | Port only the task/result/context-budget pattern into local typed contracts and compare context tokens/call count. | **ADAPT** patterns; do not adopt hosted stack. |
| [all-agentic-architectures](https://github.com/FareedKhan-dev/all-agentic-architectures) | Pattern catalog: deterministic picker, adaptive/corrective RAG, blackboard, meta-controller, verification and bounded reflection. | Repository license and maintenance require verification before copying code. Pattern catalog; implementation quality varies by example. | Use for pattern discovery; test the smallest deterministic policy pattern with FilingScope fixtures. | **ADAPT** ideas only; no broad framework dependency. |
| [SEC Filing Agent](https://github.com/Zhonghui-li/sec-filing-agent) | Potential reference for historical filing selection, SEC facts, and as-reported vs revised data. | License, maintenance, versions, and data lineage not yet audited. | Inspect source and SEC endpoint handling during M9; reproduce only a testable behavior with provenance. | **DEFER** pending source audit. |
| [Financial Filings RAG](https://github.com/marcinossolinski/financial-filings-rag) | Potential reference for FinanceBench pipeline, retrieval ablations, and reranking. | License, maintenance, dependency and resource footprint not yet audited. | Compare experiment methodology and split hygiene with P1/P5 before borrowing any code. | **DEFER** pending source audit. |
| [SEC RAG Platform](https://github.com/adwitiyashukla/sec-rag-platform) | Potential reference for hybrid retrieval, numerical facts, and groundedness regression tests. | License, maintenance, dependencies, and model/data requirements not yet audited. | Review at M9 for testable structured-fact integration ideas; keep our evidence authority deterministic. | **DEFER** pending source audit. |
| [Docling](https://github.com/docling-project/docling) and [technical report](https://arxiv.org/abs/2408.09869) | Structured document conversion with page layout, reading order, OCR and table recognition. | Python code is MIT. Model weights have their own terms. On 226 pages, ACCURATE used 52× the parse time and 39× the peak working set of pypdf. | [M10](DOCUMENT_INTELLIGENCE.md) recovered 20/20 audited header associations. Page-text Recall@10 rose from 0.50 to 0.60 overall and was 0.20 for both on validation. | **EXPERIMENT**. Keep pypdf as the default. |
| [EdgarTools](https://github.com/dgunning/edgartools) | Python filing access, XBRL parsing and financial statements. | MIT. SEC identity configuration applies. | Its [Company Facts guide](https://edgartools.readthedocs.io/en/latest/guides/company-facts/) informed the distinction between fiscal lookup and inspecting later observations for possible restatements. M9 uses a narrower resolver over the existing HTTP client. | **ADAPT** the lookup and revision concepts. |
| [Chain-of-Verification](https://aclanthology.org/2024.findings-acl.212/), [Reflexion](https://arxiv.org/abs/2303.11366) and [FEVER](https://aclanthology.org/N18-1074/) | Independent checks on a draft, feedback-driven revision and evidence-linked claim labels. | Research references. M11 uses the existing verifier and evidence with zero additional model calls. | [M11](ADVANCED_VERIFICATION.md) rechecks one correction when a specific defect is actionable. The 16-case replay measures the local policy. | **ADAPT** source checks and bounded feedback. |
| [SEC EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) | Official submissions and entity-wide facts from standard taxonomies. | Public JSON. `SECEdgarClient` requires a contact-bearing User-Agent and centralizes throttling. | M9 uses Company Facts and budgeted Submissions dates to resolve concepts, periods, units, accessions and revisions. [M9 fixture results](FINANCIAL_FACT_ARCHITECTURE.md) | **ADOPT** the official endpoints as source of record. |
| [Qdrant hybrid and multi-stage queries](https://qdrant.tech/documentation/search/hybrid-queries/) and [multivector guide](https://qdrant.tech/documentation/tutorials-search-engineering/using-multivector-representations/) | Prefetch/fusion, dense+sparse/text search, staged rescoring, and multi-vector late interaction such as ColBERT. | Official product documentation; current dependency is already pinned in requirements. Local Qdrant behavior differs from server for payload indexes; multivector storage/compute can grow with token vectors. | M2 measures candidate fusion first; M14 may test ColBERT only after R1–R6 and against dense. | **ADAPT** current feature set only after baseline diagnostics. |
| [Transformers v5 migration guide](https://github.com/huggingface/transformers/blob/main/MIGRATION_GUIDE_V5.md) and [Sentence Transformers 5.6.0 dependency metadata](https://github.com/huggingface/sentence-transformers/blob/v5.6.0/pyproject.toml) | Transformers v5 changes legacy model APIs; Sentence Transformers 5.6.0 permits Transformers `>=4.41,<6`, so the compatible major must be selected for FilingScope's pinned custom Nomic model. | Apache-2.0 projects; actively maintained. No new runtime component; the version pin constrains an existing local embedding dependency and does not change its model/resource profile. | M1 tested the 150-case P5 dry run with Transformers 5.22.2 (failed in the pinned Nomic code) and 4.57.6 (completed with 100% A0–A2 P1 replay parity). | **ADOPT** the exact 4.57.6 pin; revalidate the local model before upgrading. |

The repository URLs above are research references. Except where a license is
verified from the source's own metadata, assume no permission to copy code.
