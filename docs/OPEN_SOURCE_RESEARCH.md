# Open-source and paper research

Research status checked 2026-11-12. Findings below are design inputs and
experiment candidates; no external framework is treated as proof that FilingScope
will improve. Re-check license, versions, model terms, and resource needs before
adding a dependency or copying code.

| Source | Problem and method | License / maintenance / resource profile | Applicability and next experiment | Decision |
|---|---|---|---|---|
| [FinSAgent paper](https://arxiv.org/abs/2607.18102) | SEC QA framework combining role-specialized agents, database-aware query decomposition conditioned on a summary-level local-corpus view, and multi-path retrieval with feature-gated reranking. The authors report results across five offline benchmarks and a user-rating study. | Research preprint, not a dependency. The arXiv source did not link a public code repository; implementation/data licensing and independent reproducibility remain unverified. | M4 tested the corpus-conditioned planning hypothesis separately: BM25 Recall@10 rose 4.34 points overall and 2.22 held-out points, while p95 BM25 latency rose to 1,051 ms. This does not reproduce the paper's multi-agent/reranker system or establish answer-quality gains. | **ADAPT** the Corpus Map hypothesis only; no code or framework adoption. See [`M4 results`](CORPUS_AWARE_PLANNING.md). |
| [FinRank paper](https://arxiv.org/abs/2608.07400) and [dataset repository](https://github.com/datanxt/FinRank) | 1,185 manually authored records across 22 companies. It measures pooled ranking and within-question hard-negative discrimination separately. | The repository labels its release CC BY-NC 4.0. The authors disclose annotation and distribution limitations. | [M12](HARD_NEGATIVE_RETRIEVAL.md) applied the global and pairwise scoring design to existing P1 passages and independently authored judgments. | **ADAPT** the scoring design. |
| [Fin-RATE paper](https://arxiv.org/abs/2602.07294) and [dataset card](https://huggingface.co/datasets/GGLabYale/Fin-RATE) | Separates within-disclosure detail, cross-entity comparison, and longitudinal tracking. | The data card declares MIT. No dataset or dependency was acquired. | M12 includes within-disclosure, cross-company, and longitudinal evidence confusions. | **ADAPT** taxonomy. |
| [When the Reranker Becomes the Decision Layer](https://levelup.gitconnected.com/when-the-reranker-becomes-the-decision-layer-de7309e5efd7) | Describes Jev's Noul/Choice/Score decision primitives for pre-retrieval gating, candidate scoring, citation checks, and cost-aware routing, with deterministic ordering around model outputs. | Secondary practitioner article, not independent validation. Its demonstration compares five pipelines on eight in-scope and two out-of-scope questions over a small corpus; results do not transfer to financial filings. No dependency/license relevance. | M3 adapted the decision-boundary pattern into typed observations plus deterministic policy, and compared it to a score-only baseline on 60 synthetic cases. A real Jev/TypeSafe backend remains a separately gated experiment requiring external financial labels, privacy/cost review, and probability calibration checks. | **ADAPT** the architecture hypothesis; **DEFER** Jev. |
| [LangGraph](https://github.com/langchain-ai/langgraph), [StateGraph](https://reference.langchain.com/python/langgraph/graph/StateGraph), and [Send](https://reference.langchain.com/python/langgraph/types/Send) | Typed graph state and dynamic dispatch of independent tasks. | MIT. FilingScope pins `langgraph==1.2.20`. | M5 and M7 provide bounded routes. M8 uses Send, a deterministic receipt reducer and [RunnableConfig concurrency](https://reference.langchain.com/python/langchain-core/runnables/config/RunnableConfig) for scoped filing retrieval. | **ADOPT** finite routing and bounded filing fan-out. [M8 latency and limits](PARALLEL_RESEARCH.md) |
| [Deep Agents financial research](https://github.com/langchain-samples/deep_agent_financial_research/blob/main/docs/TECHNICAL.md) | Scoped collection and analysis agents use an in-memory work area, typed report, and explicit step, time and token budgets. | October 2026 activity. GitHub metadata lists no SPDX license. The sample uses DeepAgents and hosted LLMs, with optional LangSmith and Snowflake MCP. | M8 applies isolated task receipts and budgets with deterministic workers. M13 measures calls, evidence tokens and handoff correctness. | **ADAPT** context isolation and task contracts. |
| [all-agentic-architectures](https://github.com/FareedKhan-dev/all-agentic-architectures) and its [blackboard example](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/main/src/agentic_architectures/architectures/blackboard.py) | Categorical observations feed a deterministic picker. The blackboard example uses shared state and multiple model bids per round. | MIT, June 2026 activity. LangGraph and optional retrieval/provider extras. Bidding uses a model call per worker plus execution. | M3 tests the deterministic picker. M6 applies shared state with evidence IDs. M11 applies bounded revision and M13 compares routing against forced research. | **ADAPT** typed observations and shared state. **REJECT** model bidding for this workflow. |
| [SEC Filing Agent](https://github.com/Zhonghui-li/sec-filing-agent) and its [evaluation protocol](https://github.com/Zhonghui-li/sec-filing-agent/blob/main/docs/EVALUATION.md) | Company Facts aliases handle tag drift and preserve original filing basis. Its paired per-case regression gate tracks new unsupported outputs. | MIT, October 2026 activity. Hosted OpenAI inference, pgvector and EDGAR ingestion. Its full benchmark requires provider access. | M9 tests tag and accession alignment, original versus changed values, and conflicting revisions. M13 scores paired outputs on source slots. | **ADAPT** revision-aware facts and per-case comparison. |
| [Financial Filings RAG](https://github.com/marcinossolinski/financial-filings-rag) | Company/period routing and a LightGBM LambdaRank reranker over a fixed 50-page candidate pool. The project groups folds by company to control gold-page leakage. | MIT, one commit in October 2026. CPU WordLlama, BM25 and LightGBM. The project reports approximately 45 ms per query with reranking. | M2 and M12 measure metadata and candidate ceilings separately. M14 compares fixed-pool reranking on frozen splits. | **ADAPT** paired fixed-pool evaluation and leakage controls. **DEFER** supervised ranking pending a separate label set. |
| [SEC RAG Platform](https://github.com/adwitiyashukla/sec-rag-platform) and its [XBRL fact store](https://github.com/adwitiyashukla/sec-rag-platform/blob/main/src/secrag/ingest/xbrl.py) | Separate dense, lexical and learned-sparse retrieval arms, cited numerical facts, and per-stage regression checks. The fact store uses annual end-year buckets and standard US GAAP aliases. | MIT, August 2026 activity. CPU ONNX BGE and SPLADE, Qdrant, pandas and optional hosted providers. | M2 compares retrieval arms. M9 tests filing fiscal intervals and Decimal values. The source fact store's annual approximation would lose requested quarter and revision distinctions. | **ADAPT** separate retrieval and evidence checks. **REJECT** the annual end-year approximation. |
| [Docling](https://github.com/docling-project/docling) and [technical report](https://arxiv.org/abs/2408.09869) | Structured document conversion with page layout, reading order, OCR and table recognition. | Python code is MIT. Model weights have their own terms. On 226 pages, ACCURATE used 52× the parse time and 39× the peak working set of pypdf. | [M10](DOCUMENT_INTELLIGENCE.md) recovered 20/20 audited header associations. Page-text Recall@10 rose from 0.50 to 0.60 overall and was 0.20 for both on validation. | **EXPERIMENT**. Keep pypdf as the default. |
| [EdgarTools](https://github.com/dgunning/edgartools) | Python filing access, XBRL parsing and financial statements. | MIT. SEC identity configuration applies. | Its [Company Facts guide](https://edgartools.readthedocs.io/en/latest/guides/company-facts/) informed the distinction between fiscal lookup and inspecting later observations for possible restatements. M9 uses a narrower resolver over the existing HTTP client. | **ADAPT** the lookup and revision concepts. |
| [Chain-of-Verification](https://aclanthology.org/2024.findings-acl.212/), [Reflexion](https://arxiv.org/abs/2303.11366) and [FEVER](https://aclanthology.org/N18-1074/) | Independent checks on a draft, feedback-driven revision and evidence-linked claim labels. | Research references. M11 uses the existing verifier and evidence with zero additional model calls. | [M11](ADVANCED_VERIFICATION.md) rechecks one correction when a specific defect is actionable. The 16-case replay measures the local policy. | **ADAPT** source checks and bounded feedback. |
| [SEC EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) | Official submissions and entity-wide facts from standard taxonomies. | Public JSON. `SECEdgarClient` requires a contact-bearing User-Agent and centralizes throttling. | M9 uses Company Facts and budgeted Submissions dates to resolve concepts, periods, units, accessions and revisions. [M9 fixture results](FINANCIAL_FACT_ARCHITECTURE.md) | **ADOPT** the official endpoints as source of record. |
| [Qdrant hybrid and multi-stage queries](https://qdrant.tech/documentation/search/hybrid-queries/) and [multivector guide](https://qdrant.tech/documentation/tutorials-search-engineering/using-multivector-representations/) | Prefetch/fusion, dense+sparse/text search, staged rescoring, and multi-vector late interaction such as ColBERT. | Official product documentation. The existing client is pinned. Local payload indexes differ from the server and multivector storage grows with the number of token vectors. | M2 measures fusion. M14 tests local multivector MaxSim after R1–R6 and matches all 24 NumPy rankings. | **EXPERIMENT** with local multivector parity. |
| [ColBERTv2](https://huggingface.co/colbert-ir/colbertv2.0) and [FastEmbed](https://qdrant.tech/documentation/fastembed/fastembed-colbert/) | Token-level MaxSim ranking over dense candidates. | The checkpoint declares MIT. M14 uses FastEmbed 0.9.1, ONNX Runtime 1.31.1 and the pinned Qdrant client. The CPU experiment used 437 MB of model files and 88 MB of vectors. | [M14](ADVANCED_RETRIEVAL.md) improved Recall@10 from 0.5625 to 0.8056 and lost one additional curated pair. Local Qdrant reproduced NumPy rankings with higher added latency. | **EXPERIMENT** with direct MaxSim and retain Qdrant for parity. |
| [GraphRAG](https://github.com/microsoft/graphrag) | Entity-to-text, relationship and community retrieval. | MIT. The project describes its current status as maintenance mode. The full index uses LLM extraction. | [M14](ADVANCED_RETRIEVAL.md) tested issuer-to-filing-to-text traversal on the local corpus. Recall@10 was 0.7708 with 0.457 ms added p95. | **ADAPT** local traversal in the experiment. |
| [HippoRAG](https://github.com/OSU-NLP-Group/HippoRAG) | Personalized PageRank over a knowledge graph for associative retrieval. | MIT research repository with a HippoRAG 2 implementation. The full pipeline uses extraction and retrieval models. M14's local graph used existing NumPy. | [M14](ADVANCED_RETRIEVAL.md) diffused query and dense seeds through filing metadata and topic links. Recall@10 was 0.8333 with 0.831 ms added p95. | **ADAPT** PageRank in the experiment. |
| [LightRAG](https://github.com/HKUDS/LightRAG) | Dual-level entity and relationship retrieval. | MIT. The repository provides maintained graph and model integrations. M14 used no additional package or model. | [M14](ADVANCED_RETRIEVAL.md) fused issuer-local and issuer-topic relationship rankings. nDCG@5 was 0.5647 with 0.442 ms added p95. | **ADAPT** dual-level ranking in the experiment. |
| [Transformers v5 migration guide](https://github.com/huggingface/transformers/blob/main/MIGRATION_GUIDE_V5.md) and [Sentence Transformers 5.6.0 dependency metadata](https://github.com/huggingface/sentence-transformers/blob/v5.6.0/pyproject.toml) | Transformers v5 changes legacy model APIs; Sentence Transformers 5.6.0 permits Transformers `>=4.41,<6`, so the compatible major must be selected for FilingScope's pinned custom Nomic model. | Apache-2.0 projects; actively maintained. No new runtime component; the version pin constrains an existing local embedding dependency and does not change its model/resource profile. | M1 tested the 150-case P5 dry run with Transformers 5.22.2 (failed in the pinned Nomic code) and 4.57.6 (completed with 100% A0–A2 P1 replay parity). | **ADOPT** the exact 4.57.6 pin; revalidate the local model before upgrading. |
